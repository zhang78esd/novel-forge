# 失败模式诊断：为什么读者不追

## R — 原文 (Reading)

> 1. **虚假悬念** — 制造紧张但结果是误会 / 2. **机械降神** — 突然出现从未提及的解决方案 / 3. **过度留白** — 留下太多未回答问题 / 5. **同质悬念** — 每章都用同一种类型的钩子结尾

## I — 方法论骨架 (Interpretation)

「不好看」可以拆成可定位的故障，而不是笼统的「文笔不行」。四类高频故障：

- **追读故障**：虚假悬念（结果是误会）、机械降神（解决方案没埋过）、过度留白（一章不答任何旧悬念）、同质悬念（每章同一个钩子）、低风险钩子（晚饭吃什么）、章末总结/讲道理把悬念解释没了。
- **阅读噪音**：设定名词首现不给类别与可感知特征；无效开头（天气、洗漱、回顾上章、规则说明）；信息倾倒。
- **注水与拼接**：无意义风景、凑字数回忆、重复已知信息；章末钩子后追加场景造成「第二个结尾」；扩写留内部标记。
- **长篇崩坏**：时间线矛盾、设定崩坏、人物 OOC、重复情节、信息泄露、伏笔死结。

诊断顺序：先定位到具体段落，再判断属于哪一类，最后给出对应能力卡的处理路径。判据统一用「删掉这段，故事是否变差」。

## A1 — 应用案例 (Past Application)

**原仓库案例**：`hook-techniques.md` 给出成对反例——「他听到了脚步声...原来是猫」（虚假悬念）vs「他听到了脚步声...但追他的人已经死了」；「她突然想起自己会武术」（机械降神）vs「她想起父亲教过的防身术（第五章提过）」。`Chinese-WebNovel-Skill/SKILL.md` 另列章末反例：不要收在总结句、讲道理、情绪已散尽、解释把悬念解释没了。

**合成演练**：读者反馈「第 6 章弃书」→ 定位到章末「他不知道晚饭吃什么」属低风险钩子，且连续 4 章都用「突然揭示」→ 判定同质悬念 + 低风险钩子 → 换「两难选择」并把种子前移到本章前 20% → 交 `chapter-craft` 重写结尾。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 读者/编辑说「不追了」「AI 味重」「看不懂」，但没说具体哪里。
2. 想给一章或前 3 章做一次完读率诊断。
3. 写到中段发现节奏塌了，不知道是哪种问题。
4. 改稿前想先要一份问题清单，而不是直接改。

### 语言信号
- "为什么没人追 / 数据掉了 / 这章哪里有问题"
- "开头劝退 / 看不懂设定 / 太水了"
- "帮我诊断一下 / 找问题"
- "diagnose / why readers drop off / pacing problem"

### 与相邻能力的区分
- 与 `review-gate`：审查卡按六类底线问题与字数做**全量校验**，本卡是**症状驱动的快速定位**，输出的是问题分类与转派路径。
- 与 `deslop`：本卡判定「AI 味」属表达、用笔还是故事层，再转去味卡执行改写。
- 与 `chapter-craft` / `foreshadow-ledger`：本卡不直接改稿，只给修复去向。

## E — 可执行步骤 (Execution)

### 输入契约
必需：待诊断文本（至少一章）、症状描述（弃书位置、反馈原话，可为空）。
只有反馈没有文本时，先要文本，不凭常见套路猜。

### 步骤
1. **定位症状**：把「不好看」翻译成可观察现象（弃书章号、卡住的句子、弃读时的疑问）。完成标准：至少一条具体位置。
2. **逐类排查**：按追读故障 / 阅读噪音 / 注水拼接 / 长篇崩坏四类过一遍。完成标准：每条结论附段落位置与原文片段。
3. **判定主因**：区分「结构问题」与「表达问题」。完成标准：给出 1 个主因 + 不超过 2 个次因，不列十项泛泛建议。
4. **给修复去向**：主因 → 对应能力卡（如钩子问题转 `chapter-craft`、信息泄露转 `information-boundary`、AI 腔转 `deslop`、一致性转 `review-gate`）。完成标准：每个问题有唯一去向。
5. **验收判据**：写明改完怎么算好（如「本章至少答一个旧悬念、钩子类型与前 3 章不重复」）。完成标准：判据可检验，不是「更自然」。

### 输出契约
问题清单（位置 / 类别 / 依据 / 修复去向）+ 主因结论 + 验收判据。判停：用户要的是「直接帮我改」时，交付清单后转对应能力卡，不在此卡内改稿。

## B — 边界 (Boundary) ★

- **不要**把「删掉这段，故事是否变差」当成万能判据；它只适用于注水类问题，不适用于因果与信息边界。
- **不要**给出十条泛泛建议；主因最多一个、次因最多两个。
- **不要**把题材偏好问题（读者不爱这个类型）误判为技术故障。
- **不要**用本卡代替全量一致性审查，那是 `review-gate` 的职责。
- 涉及平台数据（留存、完读率）时，没有真实数据要如实说明，不编数字。
