# 断点续写与分层上下文组装

## R — 原文 (Reading)

> 子agent输入上下文（每个Agent只拿自己需要的，不拿全书）：1. 负责章节的细纲（仅 1-3 章）2. 主角与本章相关人物的设定卡（精简版）3. 世界观术语表（只含本章会用到的名词）4. 上一章结尾摘要 + 下一章开头目标（各 100 字内，用于衔接）
>
> — `xindoo/sumeru/skills/sumeru-write/SKILL.md`·子agent输入上下文

> 查找含 `02-写作计划.json` 且 `status` 为 `"in_progress"` 或 `"validating"` 的项目 - 如果找到未完成项目：- 展示项目信息：小说名称、完成进度（X/Y 章已完成）
>
> — `PenglongHuang/chinese-novelist-skill/references/flows/phase0-initialization.md`·中断续写检测

> 创建或修改长篇故事文件前，按下表读完当前时刻的文件（这张表是唯一的读取清单）；只读本文件、`rg` 检索或摘读都不算。
>
> — `zenstory-ai/oh-story-claudecode/skills/story-long-write/SKILL.md`·写前必读（强制）

## I — 方法论骨架 (Interpretation)

长篇写到第 30 章后质量下降，多半不是模型变笨，而是上下文被稀释或早期设定被挤掉。两个机制配合解决：

- **断点续写**：每个项目用状态文件（写作计划 JSON）记录章节状态；新会话开始先扫未完成项目，展示进度让用户选「继续 / 新作品」；从 `in_progress` 或第一个 `failed` 章接着写。计划文件损坏时用章节摘要与文件存在性重建状态。
- **分层上下文组装**：写第 N 章时只投喂六类精简材料——本章细纲、相关人物精简卡、本章用得到的术语、上章结尾摘要与下章开头目标（各 100 字内）、本章知识边界、待回收伏笔。绝不整本加载。

写前重读是硬门槛（不是 `rg` 检索、不是摘读），`wordflowlab/novel-writer-skills` 的 9 项强制重读清单把每次约 1700 token 的重载视为长期质量保险。

## A1 — 应用案例 (Past Application)

**原仓库案例**：`chinese-novelist-skill` 的 Phase0 自动检测中断项目并给出「继续/新作品」选项；`phase3-writing.md` 规定并行写入时共享文件只用 Edit 且改前重读，禁止整体重写。`Novel-Control-Station-Skill` 的「检索切片」在设定图密度高时只取本章相关节点与边，且图仅作派生视图，不得覆盖标准文件。

**合成演练**：新会话说「接着写」→ 扫到 `02-写作计划.json` 显示 18/40 章、第 19 章 `in_progress` → 只读第 19 章细纲、3 张人物卡、7 条术语、第 18 章结尾 100 字、2 条未结伏笔 → 开写，不载入前 18 章全文。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 新会话要接着上次写。
2. 写到中段开始忘设定、重复桥段。
3. 上下文快满，需要精简投喂。
4. 并行写作时给子 Agent 分配章节材料。

### 语言信号
- "接着写 / 继续上次 / 断点续写"
- "前面写到哪了 / 帮我恢复上下文"
- "写到后面老是忘设定"
- "resume / continue from checkpoint / context slice"

### 与相邻能力的区分
- 与 `state-ledger`：底账定义「记什么」，本卡定义「怎么读回来」。
- 与 `parallel-writing`：并行卡管任务分配与写回协议，本卡只管单 Agent 的上下文切片。
- 与 `chapter-craft`：本卡是写前准备，不产出正文。
- 与 `import-legacy`：旧稿/外部稿件逆向导入走导入卡，不走断点检测。

## E — 可执行步骤 (Execution)

### 输入契约
必需：项目目录与状态文件；若无状态文件，需用户确认是「新作品」还是「已有稿件导入」。
状态文件损坏时不猜，按章节摘要与文件存在性重建。

### 步骤
1. **扫断点**：查未完成项目并展示「小说名 / X of Y 章 / 当前章状态」。完成标准：用户明确选「继续」。
2. **确定时刻**：判断当前是定方向、定设定、出细纲、写一章、日更还是大修。完成标准：对应「写前必读清单」已列出。
3. **整份重读**：按清单读必需文件，缺文件即停。完成标准：不是检索命中、不是摘读。
4. **组装切片**：六类材料，每类只取本章相关部分；上章结尾/下章目标各 ≤100 字。完成标准：切片里没有与本章无关的卷纲与专名。
5. **开写与回写**：写完按 `state-ledger` 提交，更新状态文件与章节摘要。完成标准：`status` 从 `in_progress` 变为 `completed`，填入字数。

### 输出契约
一份上下文切片清单 + 更新后的状态文件。判停：用户说「开新书」时转 `project-bootstrap`，不做断点扫描。

## B — 边界 (Boundary) ★

- **禁止**用 `rg` 检索或摘读冒充「写前重读」——`oh-story` 把这条写成强制条款。
- **禁止**把 state.json、索引、向量库当事实源；它们是投影层。
- 并行写入共享文件时只用 Edit 且改前重读，禁止 Bash 整体重写。
- 切片过窄会漏掉跨卷约束：涉及卷末高潮、长弧揭示的章节要额外带上对应伏笔记录。
- 不要把「继续」误解为授权无限连写；开书/日更范围要显式确认（见 `parallel-writing`）。
