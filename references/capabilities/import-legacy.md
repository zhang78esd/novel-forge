## I — 方法论骨架 (Interpretation)

已发过前 20 章的旧稿，价值不在「读一遍」，而在反向解析成一套可继续生产的项目结构：设定、大纲、逐章事实、追踪底账、伏笔台账。流程是五阶段，顺序不能反：

1. 确认来源、篇幅、残稿处理、外部对标；
2. 用拆文管道做深度分析（不是人工摘抄）；
3. 把分析**迁移**成项目结构，并逐批反推细纲；
4. 长篇才初始化追踪底账（短篇不建）；
5. 汇报并设当前活动书。

最关键的边界是「导入源」与「对标书」硬隔离：自己的旧稿是分析对象，不是外部参考；若把它登记成对标，后续拆文会变成自我抄袭、设定串戏。未指定外部对标时就不建对标目录。

## A1 — 应用案例 (Past Application)

**原仓库做法**：`oh-story-claudecode` 的 `story-import` 把已有 20 章反向解析后，能直接接着写第 21 章，不需要重新喂设定；分析产物落在「拆文库/{导入书名}/」，项目结构落在独立目录，追踪用 `tracking_commit.py init` 建立。

**合成演练**：导入 18 章都市旧稿 → 深度分析产出逐章事实表与人物状态 → 迁移为「设定/大纲/正文/追踪」四目录 → 第 19 章细纲由已有伏笔反推 → 初始化底账 → 设 `.active-book` → 交给 `continuation` 续写。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 已有前若干章旧稿，想接着写但不想重喂设定。
2. 从别的工具/平台迁来的半成品，需要标准化项目结构。
3. 要把一部完本拆成可复用的设定与台账。
4. 换了 Agent 环境，旧项目没有追踪文件。

### 语言信号
- "导入前面写的 20 章 / 从旧稿接着写"
- "把这些章节反向解析成设定"
- "迁移项目 / 建追踪"
- "import existing manuscript / reverse into project"

### 与相邻能力的区分
- 与 `project-bootstrap`：旧稿导入**不重新做定位问答**，避免覆盖既有设定。
- 与 `deconstruct`：本卡先调用拆文管道，但目的是「迁移成自己的项目」而非「产出对标报告」。
- 与 `continuation`：本卡建工程，续写卡从工程恢复上下文。
- 与 `state-ledger`：本卡初始化底账，之后所有回写归底账卡管。

## E — 可执行步骤 (Execution)

### 输入契约
必需：旧稿文本（分章）、篇幅判定（长篇/短篇）、残稿范围说明。
只有书名没有正文时停止，不凭记忆导入。

### 步骤
1. **确认边界**：来源、篇幅、残稿处理、是否另有外部对标。完成标准：导入源与对标源在目录上分开。
2. **深度分析**：走 `deconstruct` 管道产出逐章事实与跨章观察。完成标准：事实附章节定位，缺失写「未知」。
3. **结构迁移**：建设定、大纲、正文、追踪目录；逐批反推已有章细纲。完成标准：正文与细纲可相互定位。
4. **初始化底账**：仅长篇建立追踪并提交首版状态。完成标准：短篇不建追踪体系。
5. **汇报与激活**：列出可续写章节、未结伏笔、设定缺口，设当前活动书。完成标准：后续会话可从文件接上。

### 输出契约
标准化项目结构 + 导入报告（章节覆盖、未结项、缺口）。判停：用户只想「总结旧稿讲了什么」时交付到步骤 2 的报告即可。

## B — 边界 (Boundary) ★

- **禁止**把导入源登记为主/副对标，或把导入分析产物复制进对标目录——这是全流程硬约束。
- **不要**为旧稿重做定位问答或改写既有设定；缺什么标什么，不擅自补全。
- **不要**虚构未写章节的事实；残稿边界之外的部分写「未知」。
- 短篇不初始化长篇追踪体系。
- 旧稿涉及他人版权作品时，只做自有续写工程，不做风格复刻。
