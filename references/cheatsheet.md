# 决策规则速查 — 中文小说创作能力合集：GitHub 写小说 Skill 榜单九源蒸馏

| 能力 | 一句话规则 |
|---|---|
| 开书定位与创作合同 | 先三层问答定定位，再固化四类故事承诺，最后建设定与事实词典；没有词典不许动笔。 |
| 扫榜选材：找重复模式，不追单本爆款 | 单本爆款只是线索，多榜多作品的近期重复模式才支持趋势判断；只迁移抽象机制。 |
| 拆文：只迁移抽象机制，不复刻表达 | 建索引→逐块只读一次→抽象成功能位与「动作+结果+代价」；专名零命中、连续重合 ≤12 字。 |
| 大纲与节奏：卷纲、细纲、爽点密度 | 先查上一卷三条承接项，再按小 3–5 / 中 10–15 / 大 30–50 章布爽点，金手指必写来源·限制·成长空间。 |
| 唯一底账：状态文件与每章强制回写 | 写前真源/写后真源/投影层三层分开，所有写入经唯一提交口，投影文件禁止手改。 |
| 信息边界：作者真相与读者已知分离 | 维护客观发生与文本披露两条时间线，正文只能用「读者已知」栏，角色只能用自己已知的信息。 |
| 伏笔账本与承诺兑现 | 每个 setup 只许有一条记录，按 planned→planted→paid-off 推进；到期必兑，弃用要标弃用。 |
| 逐章写作：黄金法则、四问与悬念钩子 | 写前答四问，钩子从前 20% 播种、末 10% 收获，短中长三条悬念弧并行，停在变化那一拍。 |
| 短篇与爽文：情绪驱动单支点 | 短篇只有一个支点：要交付的那一种情绪；按情绪节点推进，场景完成职责就收，不加戏凑长度。 |
| 断点续写与分层上下文组装 | 新会话先扫断点，按当前时刻整份重读该读的文件，只投喂本章相关的六类切片，绝不整本加载。 |
| 去 AI 味：确定性预检 + 三层诊断 | 确定性规则只负责定位硬伤，三层扫描负责读感；零命中不等于没问题，不许靠加戏制造真人感。 |
| 审查、字数校验与阶段门禁 | 审查是找问题不是背书；字数必须脚本判定；阶段交接必须过可执行校验，失败只重跑失败阶段。 |
| 写作模式与无人值守连写 | 模式与章节范围必须显式确认；无人值守不打断用户，但每章内部控制步骤一个都不能少。 |
| 逆向导入：把旧稿变成可续写工程 | 先拆文再迁移成项目结构，长篇才初始化底账；导入源绝不能登记成对标书。 |
| 失败模式诊断：为什么读者不追 | 把「不好看」拆成追读故障/阅读噪音/注水拼接/长篇崩坏四类，给主因与唯一修复去向。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
