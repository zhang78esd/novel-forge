## I — 方法论骨架 (Interpretation)

开书不是先动笔，而是先签一份「创作合同」。合同有三层：

1. **定位层**：用递进式问答把含糊想法压成题材、主角、核心冲突；不要一次问完，先问必答三项，再问规格项。
2. **承诺层**：明确这本书稳定向读者提供什么——爽点、情绪点、反转点、长线期待。后续每章都要回头核对有没有赖账。
3. **词典层**：设定名词、数字事实、伏笔、计划揭示章，先登记再写。数字与年龄不许现场编。

三者共同构成后续所有能力的「写前真源」。缺任一层就开写，长篇必然漂移。

## A1 — 应用案例 (Past Application)

**案例（原仓库示例）**：`Chinese-WebNovel-Skill/SKILL.md` 的选材诊断给出一个反例点子「一个普通女孩在成长中寻找自我」，判定为「题材不清 / 事件不清 / 卖点不清 / 追更动力不清」；要求压成「题材 / 卖点 / 麻烦 / 追更原因 / 长度」五句。同一文件给出的合格 premise 写法是「女主被家族当成献祭品送往河中……想把死局变成踏入仙门的唯一机会」——只写主角处境与当前麻烦，不铺门派势力。

**合成演练**：输入「想写个都市异能」→ 三层问答收敛为「题材：都市异能；主角：被开除的鉴定师；核心冲突：他能看见物品的真实来历，但说真话会害死人」→ 承诺四类填「爽点：打脸鉴定；情绪点：被误解；反转点：来历反噬；长线期待：源头的身份」→ 词典登记「蓝晶｜首现第1章｜读者已知：贵重晶体｜完整真相：储存记忆｜计划揭示：第8章」。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 用户只有一个模糊点子，要开始一本新书。
2. 已有大纲但说不清「读者为什么追」，需要补故事承诺。
3. 开写前要建项目目录与设定词典。
4. 读到中途发现设定/数字自相矛盾，回查是不是当初没登记。

### 语言信号
- "帮我开一本新书 / 我有个点子 / 从零写一部小说"
- "这个设定能写吗 / 帮我定题材和主角"
- "先搭个框架 / 建个项目"
- "start a novel / define the premise / story bible"

### 与相邻能力的区分
- 与 `trend-scan`：本卡定「我要写什么」，`trend-scan` 定「市场在要什么」，后者在选材阶段前置。
- 与 `outline-architecture`：本卡产出定位+承诺+词典，`outline-architecture` 才把它铺成卷纲与爽点排布。
- 与 `import-legacy`：已有旧稿要续写时走导入，不要重新做定位问答覆盖原设定。

## E — 可执行步骤 (Execution)

### 输入契约
必需：题材方向（可含糊）、篇幅量级（短篇/长篇）。可选：目标平台、已有设定草稿。
缺失「篇幅量级」时只问这一项，不静默猜；其余按默认值并显式告知。

### 步骤
1. **三层问答**：Layer1 收题材/主角/核心冲突；Layer2 合并问世界观、视角基调、读者定位、章数；Layer3 生成 3–5 个候选标题。完成标准：三项必答齐全，且能一句话说清「谁在什么处境下想要什么、被什么挡住」。
2. **压成五句**：题材 / 卖点 / 麻烦 / 追更原因 / 长度。完成标准：五句都不含「成长」「寻找自我」类抽象词；否则退回补问。
3. **固化故事承诺**：填爽点、情绪点、反转点、长线期待四类。完成标准：每类至少一条可检验的兑现方式。
4. **建设定与事实词典**：四栏（名词/事实｜首现章节｜读者已知｜完整真相｜计划揭示）。完成标准：所有准备在第 1 章出现的专名与数字都已登记。
5. **落盘并交接**：写定位卡、承诺卡、词典三份文件，再进入大纲。完成标准：文件可被下一能力读取，且不含 `[待定]`、`{占位}` 等占位符。

### 输出契约
三份纯文本/Markdown 文件 + 一句「本书承诺」摘要。判停：用户只要求「给个主意」时，交付到步骤 2 即停，不建项目目录。

## B — 边界 (Boundary) ★

- **不要**把创作合同写成世界观说明书：`Chinese-WebNovel-Skill/SKILL.md` 明确「不要只给世界观，不给前几章方案」「不要空谈人物要立体」。
- **不要**一次性问卷轰炸：递进式问答的价值在于分层，合并提问每问不超过 4 个选项。
- **不要**现场编数字：年龄、日期、金额、人数、距离，词典里没有就先登记。
- 已有书稿的续写、逆向导入不走本卡，避免用新问答覆盖既有设定。
- 失败模式：只写「庞大的世界、很多势力」而无主角当前麻烦，是选材诊断里被明确点名的无效 premise。
