# 逐章写作：黄金法则、四问与悬念钩子

## R — 原文 (Reading)

> 1. **展示而非讲述** - 用动作和对话表现，不要直接陈述 / 2. **冲突驱动剧情** - 每章必须有冲突或转折 / 3. **悬念承上启下** - 每章结尾必须留下钩子
>
> — `PenglongHuang/chinese-novelist-skill/SKILL.md`·三大黄金法则

> 1. 主角这章想做什么 2. 谁或什么阻止他 3. 这章结束后局面变成什么 4. 为什么读者还要往下看
>
> — `Tomsawyerhu/Chinese-WebNovel-Skill/SKILL.md`·每章必须回答四件事

> 1. **播种（前20%）** / 2. **生长（中间60-70%）** / 3. **收获（最后10%）** ——章节结尾，种子突然开花结果。
>
> — `PenglongHuang/chinese-novelist-skill/references/guides/hook-techniques.md`·三段式设计法

> 读者翻开下一章的理由，永远要在这一章的结尾给够。一次只留一个悬念不够——至少要让读者同时惦记着两件事。
>
> — 同上·跨章悬念弧

## I — 方法论骨架 (Interpretation)

一章不是「三千字」，而是「一次局面变化 + 一个让读者翻页的理由」。四件事必须在写前想清：主角要什么、谁挡、局面变成什么、为什么还往下看。缺任一件就是水章。

钩子不是写到结尾临时加的，而是三段式：前 20% 播种一个看似无关的细节，中段让它偶尔冒头，末 10% 兑现成钩子并升级。具体手法有两套模板可轮换——章末「悬念钩子十三式」（突然揭示、紧急危机、未完成动作、身份反转、两难选择、神秘物品、时间限制、承诺威胁、离奇消失、言外之意、意象、回声、留白），章首「引子七式」（悬念对话、闪前碎片、倒计时、神秘独白、反差场景、未完成动作、意象伏笔，50–150 字）。

跨章要跑短弧 2–3 章、中弧 5–8 章、长弧全书，三线并行；强度按 1–5 级波浪式递进，不要每章都上生存级悬念。

## A1 — 应用案例 (Past Application)

**原仓库案例**：`hook-techniques.md` 的「突然揭示」示例——「警官看着死者的手机，最后一条短信来自一个他认识的人——他自己三天前发出的号码」，三要素为信息出乎意料、改变现状理解、留下「为什么」。同文件给出三段式完整演练：播种（一条未读消息没点开）→ 生长（整天有人说她脸色不好）→ 收获（深夜点开，是三个月前投的简历约今天面试，而今天已经过了）。

**去 AI 味正反对照**（`Chinese-WebNovel-Skill/SKILL.md`）：坏「她心中五味杂陈，一时间不知道该说什么」；好「她张了张嘴，最后只把手里的杯子放回桌上。陶瓷磕出一声脆响」。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 已有细纲，要写某一章正文。
2. 章节太平、没有冲突，需要重构。
3. 开头/结尾写不出抓手感。
4. 读者反馈「不追了」「章末没劲」。

### 语言信号
- "写第 X 章 / 帮我写这一章"
- "开头怎么抓人 / 结尾怎么留钩子"
- "这章是不是水了 / 节奏太平"
- "write this chapter / chapter hook / opening line"

### 与相邻能力的区分
- 与 `outline-architecture`：细纲已定才进本卡；本卡不改卷级结构。
- 与 `deslop`：本卡负责「写得对、有钩子」，`deslop` 负责「写完后清 AI 腔」，顺序不要倒。
- 与 `short-form-emotion`：短篇按情绪与场景组织，不套长篇的章首引子与多弧并行。
- 与 `continuation`：跨会话恢复上下文归续写卡，本卡只管当前章行文。

## E — 可执行步骤 (Execution)

### 输入契约
必需：本章细纲（目标/阻碍/变化/章末拉力）、上章结尾 500–800 字、相关人物设定卡、文风基准、本章知识边界表。
缺任一必需项先读文件补齐，不得凭记忆写。

### 步骤
1. **写前四问**：填目标、阻碍、新局面、章末拉力。完成标准：四栏都具体，无「内心成长」类抽象词。
2. **选钩子并倒推播种**：从十三式选一式，在章首 20% 埋下对应种子。完成标准：末 10% 的钩子能由前文细节兑现，不是硬加。
3. **写章首引子**：50–150 字，七式选一。完成标准：不写天气、洗漱、回顾上章、规则说明。
4. **逐场推进**：每场要有目标、阻碍、变化；无变化即删。完成标准：全章至少一次不可删的局面变化。
5. **收尾**：停在变化发生的那一拍，不总结、不讲道理。完成标准：至少两条悬念线仍开着，且本章至少回答了一个旧悬念。
6. **章末自检**：钩子类型与前 3 章不重复；扩写插入点在最后一场戏开始之前（一章只能有一个结尾）。

### 输出契约
本章正文 + 300–500 字章节摘要 + 四问表。判停：用户只要「一段示例」时不启动完整流程，直接给片段。

## B — 边界 (Boundary) ★

- **五大禁忌**（`hook-techniques.md`）：虚假悬念、机械降神、过度留白、低风险钩子、同质悬念。每章至少答一个旧悬念再提新悬念。
- **不要**无效开头：天气描写、日常流程、回顾上章、过度解释（`chapter-guide.md`）。
- **不要**注水：风景堆砌、凑字数回忆、重复已知信息；判据是「删掉这段，故事是否变差」。
- **不要**在章末钩子之后追加场景，那会制造第二个结尾。
- **不要**为套技巧另造与主线无关的危机；解决方案必须前文埋过。
- 扩写时禁止出现「（补）/（扩）/（新增）」等内部标记。
