## I — 方法论骨架 (Interpretation)

审查的立场是「找茬」，不是给自己的稿子背书。三层门禁各管一件事：

- **章节级**：字数、完成度、钩子、连贯性由确定性脚本判定（模型自估字数不可信）；不合格章标记 `failed` 并回写重写，最多 3 轮，超过则保留记录不阻塞。
- **一致性级**：六类底线问题——时间线矛盾、设定崩坏、人物 OOC、重复情节、信息泄露、伏笔死结。每条问题要输出「问题 + 位置 + 参考文件行 + 当前文本 + 已建立特征」，并给三条处置分支（改正文本 / 更新档案 / 是否同名不同人），按严重度分级。
- **阶段级**：阶段交接必须过可执行校验（脚本退出码），失败写 `blocked_at`，只重跑失败阶段，带病不流入下游。

审稿结论必须由独立审查产出，禁止主流程口头总结代替；`blocking` 问题交用户裁决。审查能力不足时降级为单人模式并声明，而不是说「无法加载」就停。

## A1 — 应用案例 (Past Application)

**原仓库案例**：`wordflowlab/novel-writer-skills` 一致性警报格式——「问题：角色特征不匹配 / 位置：当前章节，第3段 / 参考：characters/mary-chen.md，第15行 / 当前文本：『玛丽的绿色眼睛眯起...』 / 已建立特征：『眼睛颜色：蓝色』（在第3章中设定）」，并给出三条分支。`oh-story/story-review` 用统一 Findings Schema（severity S1–S4 + evidence + fix）与 full/lean/solo 三模式，异常一律降级 solo。

**合成演练**：第 9 章字数 2410（下限 3000）→ 脚本退出码 1 → `status=failed`、retryCount+1 → 按「场景肌理充实」选 2 种技巧扩写（不用注水）→ 复检 3180 通过 → `status=completed`。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 一章/一卷写完，要做完成度检查。
2. 全稿交付前查一致性、字数、伏笔死结。
3. 阶段交接前确认能不能进入下一阶段。
4. 审查结果自相矛盾，需要一个可信的裁决流程。

### 语言信号
- "帮我审稿 / 检查这一章 / 有没有硬伤"
- "字数够吗 / 全稿校验"
- "能不能进入下一阶段 / 门禁过了吗"
- "review / QA / consistency check / validation gate"

### 与相邻能力的区分
- 与 `deslop`：本卡查逻辑与完成度，去味卡查语感；不要混在一次扫描里。
- 与 `foreshadow-ledger`：伏笔卡管台账推进，本卡把「伏笔死结」当一类底线问题来扫。
- 与 `state-ledger`：本卡只读检查，不自动修复项目文件；修复要走底账提交口。

## E — 可执行步骤 (Execution)

### 输入契约
必需：待审文本、字数字段与阈值、设定/人物档案、上一阶段校验结果。
脚本环境缺失时明确标注「字数未经脚本校验」，不得降级为模型估算。

### 步骤
1. **确定性预检**：字数、完成度、占位符、专名残留。完成标准：脚本退出码 0/1/2 已记录。
2. **六类底线扫描**：时间线、设定、OOC、重复、信息泄露、伏笔死结。完成标准：每条问题含位置与参考行，不给「感觉有点怪」类结论。
3. **分级与分支**：严重度分级；每条给「改正文本 / 更新档案 / 同名不同人」三分支。完成标准：blocking 项已提交用户裁决。
4. **有限轮修复**：不合格章回写重写，最多 3 轮。完成标准：超轮次保留记录、不阻塞，不死循环。
5. **阶段门禁**：交接跑可执行校验。完成标准：失败写 `blocked_at`，只重跑失败阶段。
6. **出报告**：Findings 表 + 处置结果 + 未解决项。完成标准：不伪造结论、不口头总结代替审查输出。

### 输出契约
审查报告（Findings + 严重度 + 修复状态）+ 校验日志 + 门禁结论。判停：纯错别字校对不属于本卡范围。

## B — 边界 (Boundary) ★

- **审查是找问题，不是验证正确性**——这条是铁律，不要写成「本章质量良好」的背书。
- **禁止**主流程伪造审查结论或口头总结代替独立审查输出。
- **禁止**把只读检查器改成自动修复；修复必须走底账提交。
- 字数必须脚本判定，模型估算无效；无 Node/脚本环境要如实注明未校验。
- 有意矛盾（不可靠叙述者、谎报特征）在档案注明，避免误报。
- 超 3 轮仍不合格要保留记录，不许无限重写。
