# 大纲与节奏：卷纲、细纲、爽点密度

## R — 原文 (Reading)

> 黄金爽点密度：每3-5章一个小爽点，每10-15章一个中爽点，每30-50章一个大高潮。
>
> — `xindoo/sumeru/skills/sumeru-outline/SKILL.md`·节奏参数

> 跨卷一致性检查（非首卷必须执行）：- 上一卷未回收的伏笔必须出现在新卷伏笔规划中（继续推进或标记回收）。- 角色关系变化必须延续，不能当上一卷没发生过。- 主角能力 / 境界必须承接，不回退也不跳级（除非有剧情解释）。
>
> — `lingfengQAQ/webnovel-writer/.../webnovel-plan/SKILL.md`·Step 6 卷纲骨架

> 金手指/特殊能力：来源、限制、成长空间
>
> — `xindoo/sumeru/skills/sumeru-outline/SKILL.md`·设定字段

## I — 方法论骨架 (Interpretation)

大纲要同时满足三条互相拉扯的约束：**结构承接**（上一卷的伏笔、关系、能力境界必须续上）、**节奏可售**（爽点按密度排布，铺垫→转折→爆发→余韵）、**能力不失控**（金手指必须写清来源、限制、成长空间，形成「能解释赢但不等于赢」）。

规划采用两级下钻：先卷纲（卷名、核心冲突、卷末高潮、伏笔表），再细纲到章；每章用结构化节点表达（核心事件、推进节点、结尾节点），相邻章必须承接。新增设定采取「最小写回」——只更新受影响的总纲字段，不预生成下一卷全部文件。发现总纲与设定冲突时先阻断（BLOCKER），交用户裁决，不擅自取舍。

## A1 — 应用案例 (Past Application)

**原仓库案例**：`webnovel-plan/SKILL.md` 给出结构化写回样例——`foreshadow_writeback` 数组显式记录「本卷规划明确新增的伏笔 / buried_chapter: 第10章 / payoff_chapter: 空 / level: 卷级」，并要求经总纲同步后清掉 `[待...]`、`暂名`、`{占位}` 才允许进入写章。

**合成演练**：20 章短长篇 → 小爽点排在 4/8/13/17，中爽点排 12，大高潮排 20；第 12 章回收第 3 章埋的身份伏笔；细纲每章填「目标/阻碍/变化/章末拉力」四字段。

## A2 — 触发场景 (Future Trigger) ★

### 情境
1. 定位已定，要铺第一卷或全书分卷。
2. 写到中段节奏散了，需要重排爽点。
3. 开新卷，要检查上一卷的伏笔与角色状态有没有接上。
4. 金手指太强导致后续没法写，需要补限制。

### 语言信号
- "帮我排大纲 / 分卷 / 细纲"
- "节奏是不是太慢了 / 爽点怎么安排"
- "下一卷怎么接 / 前面伏笔怎么办"
- "outline / pacing / arc structure"

### 与相邻能力的区分
- 与 `project-bootstrap`：本卡铺结构，不重新定题材与承诺。
- 与 `foreshadow-ledger`：本卡在规划期「登记」伏笔，兑现追踪由伏笔账本负责。
- 与 `chapter-craft`：细纲交到章级就停，具体行文与钩子写法归逐章写作。

## E — 可执行步骤 (Execution)

### 输入契约
必需：定位卡＋故事承诺、总章节数或卷数、已有卷纲（非首卷时必需）。
缺失已有卷纲而声称「写第二卷」时停止，先补齐再继续。

### 步骤
1. **跨卷检查**：读近 5 章摘要、未回收伏笔清单、角色状态。完成标准：三条承接项（伏笔/关系/能力境界）逐条有去向。
2. **排节奏**：按「小 3–5 章 / 中 10–15 章 / 大 30–50 章」布点，短篇按情绪曲线另排。完成标准：每 3 章内至少一次局面变化。
3. **写卷纲**：卷名、核心冲突、卷末高潮、伏笔表。完成标准：冲突可由定位卡的「核心冲突」推导。
4. **下钻细纲**：每章填目标/阻碍/变化/章末拉力，标注结构化节点。完成标准：相邻章「变化」与「目标」能接上，无 `[待定]`。
5. **冲突裁决**：总纲与设定矛盾标 BLOCKER 并停下问用户。完成标准：优先级按「用户明确要求 > 总纲核心冲突 > 时间线硬约束 > 默认流程」执行。
6. **最小写回**：只更新受影响的总纲字段。完成标准：不生成下一卷的空白文件。

### 输出契约
卷纲文件 + 章级细纲表 + 爽点排布表 + 伏笔写回数组。判停：用户只要「大概分几卷」时交付到步骤 3。

## B — 边界 (Boundary) ★

- **不要**把爽点密度当成硬配额机械套用；它是节奏诊断参数，不是每 4 章必须打脸一次。
- **不要**在细纲里预写正文或把对话写死，那是逐章写作的事。
- **不要**用「暂名」「{占位}」进入写章阶段——原仓库把占位符扫描设为门禁。
- 冲突未裁决不得继续更新；`webnovel-plan` 明确「先阻断，再等用户裁决」。
- 短篇不套用卷级循环与黄金三章模型，走 `short-form-emotion`。
